کلاینت سشنی پایدار و چندحسابی

کاربر فقط نام سشن می‌دهد؛ ورود از ترمینال انجام می‌شود و هر حساب inbox، outbox و فضای رمزگذاری‌شدهٔ جدا دارد.

شروع یک سشن چندسشنی API دریافت قراردادها امنیت

شروع سریع؛ بدون hard-code

ابتدا package را در محیط خصوصی نصب کنید. سپس برای هر حساب، یک نام سشن انتخاب کنید. این نام نه شماره تلفن است و نه token.

py -3.13 -m pip install .
fnc-rubika login personal

شماره روبیکا را با فرمت +989XXXXXXXXX وارد کنید: +989123456789
کد تایید ارسال‌شده را وارد کنید: ******
شماره، OTP، cookie و access token را در log یا source قرار ندهید. CLI آن‌ها را نمایش مجدد یا persist نمی‌کند.

الگوی درست برای یک حساب

Client خودِ کلاینت اصلی است. دیگر لازم نیست async_client() را در کد عادی صدا بزنید.

from fnc_rubika import Client

async def main() -> None:
    async with Client("personal") as client:
        sent = await client.messages.send(
            "chat-id", "سلام"
        )
        print(sent.message_id)

async_client() فقط یک escape hatch برای integrationهای سطح پایین است و همان client داخلی را برمی‌گرداند.

چرخهٔ عمر سشن

CLI شماره و OTP را می‌گیرد.
سشن با AES-256-GCM ذخیره می‌شود.
context manager receiver و outbox را شروع می‌کند.
خروج، اتصال‌ها و SQLite را می‌بندد.

مسیر دادهٔ پیش‌فرض

%LOCALAPPDATA%\fnc-rubika\personal.sqlite3

هر نام سشن فایل، cursor، صف ارسال و کلید idempotency جدا دارد.

چند حساب، یک برنامه

از SessionPool برای شروع و بستن هم‌زمان چند سشن استفاده کنید. دادهٔ اعضا با هم share نمی‌شود.

from fnc_rubika import SessionPool

async def main() -> None:
    async with SessionPool("personal", "business") as sessions:
        personal = sessions["personal"]
        business = sessions.get("business")

        await personal.messages.send("chat-a", "پیام شخصی")
        await business.messages.send("chat-b", "پیام کاری")
هر عضو pool باید پیش‌تر با fnc-rubika login <name> وارد شده باشد.

جدول کامل همهٔ ورودی‌ها، خروجی‌ها، modelها و errorها در مرجع کامل Markdown است.

دریافت قابل‌بازیابی

async with Client("personal") as client:
    async for delivery in client.events():
        try:
            await save_once(
                delivery.event.event_id,
                delivery.event.payload,
            )
        except Exception:
            await delivery.nack()
        else:
            await delivery.ack()

تحویل at-least-once است. event_id را در دیتابیس خودتان unique کنید.

ارسال قابل‌بازیابی

queued = await client.messages.send(
    "chat-id", "سلام", wait=False
)
result = await client.wait_operation(
    queued.operation_id, timeout=60
)

پس از timeout مبهم، retry تنها برای routeهایی انجام می‌شود که catalog آن‌ها را صریحاً idempotent دانسته باشد.

endpoint و WebSocket: واقعیت فعلی

catalog همراه این repository عمداً placeholder است؛ هیچ endpoint واقعی Rubika حدس یا ادعا نشده است. پس از بررسی مجاز هر contract، همان نام بدون hard-code از client.api قابل فراخوانی است.

تا وقتی catalog رسمی/بازبینی‌شده وارد نشده، login زنده و فراخوانی API واقعی فعال نیست. این یک محدودیت صریح امنیتی و پایداری است، نه قابلیت پنهان.

روش ثبت schema، pagination، OTP، handshake، heartbeat، frameهای WS و redaction در راهنمای قرارداد آمده است.

امنیت

  • کلید خارج از SQLite و در OS keyring است.
  • OTP و token log نمی‌شوند.
  • سشن منقضی‌شده خودکار login نمی‌کند.
  • فایل‌های session و salt را commit نکنید.
