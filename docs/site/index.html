02

یک سشن، یک حساب

نام سشن را بدهید؛ کلاینت چرخهٔ عمر اتصال را مدیریت می‌کند.

session.py Python 
from pathlib import Path
from fnc_rubika import Client

session_dir = Path(__file__).resolve().parent / "sessions"

async with Client("personal", data_dir=session_dir) as client:
    print(client.session_path)
    await client.send("YOUR_CHAT_GUID", "سلام")
↳

مسیر ذخیره

پیش‌فرض، personal.rubika در پوشهٔ اجرای برنامه است. با data_dir مسیر ثابتی انتخاب کنید؛ personal.rubika و personal به یک نام سشن اشاره می‌کنند.

⌘

ذخیرهٔ رمزگذاری‌شده

سشن و صف‌ها در SQLite با AES-256-GCM ذخیره می‌شوند. کلید سشن تازه با scrypt از گذرواژه مشتق می‌شود؛ keyring سیستم‌عامل لازم نیست. گذرواژه از ورودی مخفی یا متغیر FNC_RUBIKA_SESSION_PASSWORD گرفته می‌شود. فایل بسته‌شده و همان گذرواژه روی ویندوز و لینوکس قابل استفاده‌اند.

گزینه رفتار
session_name ۱ تا ۶۴ کاراکتر؛ شروع با حرف یا عدد و ادامه با حرف، عدد، خط زیر یا خط تیره.
auto_login=True ورود تعاملی در نبود سشن یا ردشدن قطعی آن؛ کد ورود و رمز با ورودی مخفی دریافت می‌شوند.
auto_login=False مناسب برنامهٔ بدون اپراتور؛ به‌جای بازکردن prompt، نبود یا رد سشن خطا ایجاد می‌کند.
has_session() وجود سشن ذخیره‌شده را بررسی می‌کند؛ به‌تنهایی اعتبار آن در سرور را ثابت نمی‌کند.
session_path مسیر کامل فایل سشن فعلی را می‌دهد.

هر فایل سشن را در اختیار یک پردازش قرار دهید. خروج از async with اتصال‌ها و store را می‌بندد؛ یک کلاینت بسته دوباره شروع نمی‌شود.

کلاینت یک نسخهٔ JPEG با حفظ نسبت تصویر آماده می‌کند. اگر تامنیل خالی، خراب یا نامعتبر باشد، ارسال عکس متوقف می‌شود؛ مرجع آپلودشده و فراخوانی مستقیم sendMessage با نوع Image هم همین شرط را دارند. فایل ارسالی می‌تواند با فایل اصلی در ابعاد، حجم و پسوند متفاوت باشد.

پارامتر پیش‌فرض کاربرد
caption None یک رشته برای کپشن؛ نبود آن یعنی بدون کپشن.
reply_to_message_id None شناسهٔ پیام برای ارسال رسانه در پاسخ به آن.
wait True انتظار برای تأیید ارسال؛ با مقدار False عملیات صف برمی‌گردد.
timeout 300 ثانیه؛ جداگانه برای آپلود و تأیید ارسال پیام.

در رسانه، آپلود حتی با wait=False ابتدا کامل می‌شود. خروجی upload_photo و upload_video از نوع MediaRef است؛ در همان حساب دوباره استفاده کنید. upload عمومی مشخصات مخصوص عکس و فیلم را آماده نمی‌کند.

05

دریافت و پردازش رویدادها

هندلر را ثبت کنید و کلاینت را برای دریافت پیوسته اجرا کنید.

events.py Python 
import asyncio
from fnc_rubika import Client

async def main():
    client = Client("personal")

    @client.on("message")
    async def on_message(_, delivery):
        # ساختار payload را مطابق نوع رویداد بررسی کنید.
        print(delivery.event.event_id)

    async with client:
        await client.run()

asyncio.run(main())

پس از موفقیت همهٔ هندلرها، رویداد acknowledge می‌شود. خطای هندلر باعث تحویل مجدد می‌شود؛ برای عملیات جانبی مهم، event_id را در ذخیره‌سازی خود یکتا کنید.

کنترل دستی ack و nack
manual_ack.py Python 
async for delivery in client.events():
    try:
        await save_once(
            delivery.event.event_id,
            delivery.event.payload,
        )
    except Exception:
        await delivery.nack()
    else:
        await delivery.ack()

save_once در این مثال تابع ذخیره‌سازی برنامهٔ شماست. ذخیرهٔ پایدار رویدادهای دریافت‌شده، بازیابی رویدادهای از‌دست‌رفته هنگام قطع اتصال را تضمین نمی‌کند.

06

تأیید ارسال را جدی بگیرید

عملیات تغییردهنده ابتدا در صف پایدار ثبت می‌شوند.

outbox.py Python 
queued = await client.send(chat_id, "سلام", wait=False)

result = await client.wait_operation(
    queued.operation_id,
    timeout=60,
)
print(result)

←
sending در حال درخواست
←
delivered تأیید سرویس

timeout به‌تنهایی عملیات را لغو نمی‌کند.

اگر نتیجهٔ ارسال نامطمئن باشد، وضعیت می‌تواند unknown شود. پیش از ارسال مجدد، پیام‌ها و وضعیت عملیات را بررسی کنید. در نبود تضمین idempotency، بازپخش خودکار انجام نمی‌شود؛ دریافت شناسهٔ پیام هم به معنی دیده‌شدن آن توسط مخاطب نیست.

وضعیت معنی
failed رد قطعی عملیات؛ خطای دسترسی یا payload را بررسی کنید.
unknown درخواست ممکن است انجام شده باشد؛ ارسال دوباره می‌تواند پیام تکراری بسازد.

هر سشن داده و صف مستقل دارد؛ رابط sync نیز همان متدهای خوانا را ارائه می‌دهد.

from fnc_rubika import Client

with Client("personal") as client:

در رابط sync از await استفاده نکنید. برای برنامهٔ async، همان async with Client(...) را به‌کار ببرید.

وقتی چیزی طبق انتظار پیش نمی‌رود

خطا را براساس مرحلهٔ وقوع آن بررسی کنید؛ ورود، آپلود و ارسال مراحل جدا هستند.

خطا معنی و اقدام
ModuleNotFoundError پکیج در مفسر دیگری نصب شده است. نصب را با همان فایل python محیط اجرا انجام دهید.
ValueError با thumbnail پیش‌نمایش عکس خالی، خراب یا خارج از اندازهٔ مجاز است. مسیر معتبر یا مرجع upload_photo را بدهید.
AccessDeniedError دسترسی به عملیات رد شده است؛ GUID مقصد و مجوز حساب را بررسی کنید. ERROR_GENERIC/INVALID_AUTH به‌تنهایی انقضای سشن را ثابت نمی‌کند.
SessionExpiredError سشن رد یا منقضی شده است. در حالت auto_login، ورود مجدد اجرا می‌شود؛ در حالت بدون prompt، ورود را جدا انجام دهید.
SessionRenewalError ورود مجدد سشن قابل استفاده نساخته است؛ علت گزارش‌شده و محدودیت‌های حساب را بررسی کنید.
OperationUnknownError نتیجهٔ عملیات قطعی نیست. پیش از تکرار، وضعیت پیام و صف را بررسی کنید.
RemoteOperationError عملیات با پاسخ قطعی سرور رد شده است؛ payload و مجوزها را بررسی کنید.
SecurityConfigurationError keyring، کلید یا فایل رمزگذاری‌شده قابل استفاده نیست.
ContractError کاتالوگ یا قرارداد درخواست ناسازگار است.
TransportError / RateLimitError مشکل اتصال یا محدودیت نرخ؛ سیاست retry و تأخیر کلاینت را در نظر بگیرید.
عیب‌یابی سشن و مقصد بدون ارسال پیام
بررسی خواندن حساب و مقصد PowerShell 
python -m fnc_rubika diagnose personal --chat-id YOUR_CHAT_GUID

این فرمان از سشن موجود استفاده می‌کند و صف ارسال یا دریافت realtime را شروع نمی‌کند. گزارش JSON شامل وضعیت دسترسی است؛ موفقیت خواندن، موفقیت ارسال را به‌تنهایی تضمین نمی‌کند.

VS Code پکیج یا متدها را نمی‌شناسد
  1. افزونه‌های Python و Pylance را نصب کنید.
  2. با Python: Select Interpreter مفسر همین محیط مجازی را انتخاب کنید.
  3. پکیج را با همان مفسر نصب کنید و در صورت نیاز Developer: Reload Window را اجرا کنید.
بررسی محیط فعال PowerShell 
python -c "import sys, fnc_rubika; print(sys.executable); print(fnc_rubika.__file__)"
python -m pip check
حفظ امنیت فایل سشن

فایل سشن، کلید، OTP و رمز دومرحله‌ای را در مخزن یا لاگ عمومی قرار ندهید. در سطح پایین AsyncClient، بستن store تزریق‌شده مسئولیت فراخوان است؛ Client store خودش را می‌بندد.
